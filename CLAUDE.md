# Parcel Portfolio — governing document

Read this before changing anything. It is the source of truth for how this app is built.

## What it is
A phone-first web app (installable to the home screen) for screening rental properties in the
Joplin, MO market: Joplin, Webb City, Carl Junction, Oronogo, Carthage, Neosho and nearby towns.
Owner: Ev. Personal tool, not a client-facing product. Not related to Kinsman.

Core jobs:
1. While driving neighborhoods: show where I am, pin a house where I'm standing, and see at once
   whether it can pay for itself.
2. Run every listing through the same five tests: rent-to-price, the manager test,
   condition (the big four), area grade, and layout.
3. Grade areas from facts (schools, income, owner-occupancy, rental vacancy, education,
   home values, housing age) plus my own local knowledge.

## Architecture
- Plain HTML/CSS/ES modules. No build step, no framework. Runs from VS Code Live Server locally
  and from GitHub Pages (HTTPS) on the phone. GPS requires HTTPS or localhost.
- `vendor/maplibre-gl.*` — MapLibre GL JS 5.x, vendored (BSD-3). Global `maplibregl`.
- Map tiles: OpenFreeMap (`tiles.openfreemap.org/styles/liberty|positron`), free, no key.
  Attribution to OpenStreetMap contributors must stay visible.
- Address search / reverse lookup: OpenStreetMap Nominatim. Policy: interactive use only,
  max 1 request per second (enforced in `src/geo.js`), never bulk-geocode.
- Storage: `localStorage` key `parcel-portfolio.v1`, schema `parcel.portfolio.v1`.
  Data lives on the device; Export/Import JSON is the backup and the way to move devices.

| File | Role |
|---|---|
| `src/finance.js` | Pure deal math and the five tests. No DOM, no storage. |
| `src/areas.js` | Area scoring, computed live from facts + overrides. |
| `src/store.js` | Load/save/export/import. Fails loudly on unknown schema. |
| `src/geo.js` | Point-in-ZIP, Nominatim search/reverse, Apple Maps links. |
| `src/app.js` | UI only: map, pins, sheet views, events. |
| `data/areas.json` | Area FACTS with provenance. Generated by `tools/build_areas.py`. |
| `data/boundaries.geojson` | ZIP and tract outlines + label points. Generated. |
| `data/seed-properties.json` | Loaded once on first run. |
| `tools/manual_inputs.json` | Hand-maintained facts (Zillow, school grades, tracts) with sources and dates. |
| `sw.js` | Offline app shell. Bump `VERSION` on every release. |

## Rules (integrity — never configurable)
1. **Store facts, compute judgments.** `areas.json` holds facts only. Scores, grades, verdicts,
   cash flow and every derived number are computed at runtime. Never persist a computed value
   as a source of truth. (A saved property stores inputs only.)
2. **Every fact carries provenance:** `state` (PRESENT / UNKNOWN), `value`, `source`, `asOf`,
   `decay`. Missing data is `UNKNOWN`, never a guessed number. Unknown facts score as regional
   average (50) and are listed on the area screen.
3. **Estimates are labeled.** A home value derived from Census × regional ratio says "est."
4. **Fail loudly.** Unreadable saved data stops the app with a message instead of starting empty.
   The build script exits on a missing ZIP.
5. **The user's data is never overwritten silently.** Import merges by id; newer `updatedAt` wins.
6. **Keep `finance.js` pure** and covered by tests. Any change to the math ships with a test
   that checks it against a hand calculation (10bII+ keystrokes in the comment are welcome).

## Policy defaults (change deliberately, note it in docs/parcel-map.md)
- Grade cutoffs: A ≥ 70, B ≥ 50, C ≥ 37, D below.
- Weights: school 20, income 20, owner-occupied 15, rental vacancy 15, bachelor's 10,
  home value 10, median year built 10.
- Grade → vacancy / appreciation: A 5/3, B 6/2.5, C 8/2, D 11/1.
- Maintenance + capex by age: ≤10 yrs 5%, ≤30 7%, ≤60 9%, older 11%.
- Management 9% of collected rent; leasing fee 50% of a month's rent per turnover; 2-year stay.
- Buy box: min rent-to-price 0.8%, strong 1.0%, target $100/door managed.
- Verdict: any fail → fail; two or more watches → close; otherwise fits.
  Condition never fails on its own (unknown ≠ bad), it asks for inspection.

## Workflow
- `npm test` (Node 20+) runs `tests/*.test.mjs`. Run before every commit.
- Local: open the folder in VS Code, right-click `index.html` → Open with Live Server.
  The service worker is disabled on localhost so edits show immediately.
- Branch + PR for anything beyond a typo; Ev reviews diffs in VS Code before merging.
- Update `docs/parcel-map.md` in the same PR whenever what's built, decided, or owed changes.
- End each Claude Code task with a short handoff summary.
- Refreshing area data: follow `docs/UPDATE-PROCESS.md`.

## Style
Apple Maps feel: full-bleed map, frosted floating controls, bottom sheet on phones (peek / half /
full), floating side card at ≥ 820 px. System font stack, iOS blue tint, semantic green/amber/red
for verdicts, grade colors A green → D red. Plain language on screen; no internal field names.
